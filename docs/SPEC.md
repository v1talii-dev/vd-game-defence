# Спецификация: браузерный Tower Defense в стиле Generals: Zero Hour

Статус: черновик v0.1 · 2026-10-18

## 1. Цели и рамки

**Что делаем:** классический tower defense в браузере. Изометрическая 2D-картинка, военный сеттинг в духе Command & Conquer: Generals — Zero Hour (типы урона против типов брони, ранги ветеранства, «пустынная» эстетика).

**MVP — вертикальный срез:** одна карта, сделанная полностью и с хорошим качеством, чтобы проверить, интересна ли сама игра.

| Параметр | Решение |
|---|---|
| Графика | 2D-изометрия, спрайты |
| Механика | Классический TD: фиксированный путь врагов, башни ставятся на разрешённые клетки, деньги за убийства |
| Режимы | Только одиночная игра, без бэкенда |
| Фракции | 1 у игрока («Коалиция») и 1 у врага («Фронт освобождения»), обе вымышленные |
| Фичи сверх базы | Апгрейды башен (3 уровня) и ранги ветеранства |
| Платформы | Десктоп (мышь + горячие клавиши) и мобильные (тач) |
| Язык | Только RU, но все строки лежат в отдельном словаре |
| Ассеты | Бесплатные паки CC0 (Kenney, OpenGameArt). Пока их нет — процедурные заглушки |

**Вне рамок MVP:** вторая и последующие карты, кампания, генеральские способности, бесконечный режим, мультиплеер, собственные юниты игрока, редактор карт.

**Юридическое:** ничего не берём из Generals — ни ассетов, ни звуков, ни названий юнитов и фракций, ни логотипов. Используем только жанр и стилистику.

## 3. Архитектура

### 3.1 Главный принцип: симуляция отделена от рендера

```
          команды (place/upgrade/sell/startWave/setSpeed)
 Vue UI ───────────────────────────────┐
   ▲                                   ▼
   │ события (throttle)       ┌──────────────────┐
   └──────────────────────────│  Симуляция (TS)  │  чистый TS, без Phaser и DOM
                              │  fixed tick 30 Гц│  детерминирована: seed + команды
   Phaser сцена ◄─ читает ────└──────────────────┘
   (рендер, интерполяция,
    ввод → команды)
```

- **Симуляция** — чистый TypeScript без импортов Phaser, Vue и DOM. Фиксированный шаг 30 тиков/с, собственный ГСЧ с seed. Одинаковые seed и список команд всегда дают одинаковое состояние: на этом держатся тесты, реплеи и отладка.
- **Phaser** только рисует: каждый кадр читает состояние симуляции, синхронизирует спрайты и интерполирует позиции между тиками. Ввод превращает в команды.
- **Vue** рисует HUD и меню. Подписывается на события симуляции (`moneyChanged`, `waveStarted`, `towerSelected`…) через Pinia-стор и не опрашивает состояние каждый кадр.
- Скорость игры (пауза / x1 / x2) — это число тиков симуляции за кадр. В тестах доступна x8 и пошаговый режим.

### 3.2 Слои FSD

Импорты разрешены только сверху вниз: `app → pages → widgets → features → entities → shared`. Каждый слайс отдаёт наружу только свой `index.ts` (public API).

```
src/
  app/            # точка входа, роутер, Pinia, глобальные стили, провайдеры
  pages/
    main-menu/
    battle/       # страница боя: собирает виджеты
    settings/
  widgets/
    battlefield/  # монтирует Phaser.Game, сцены, мост ввод → команды
    hud/          # деньги, прочность штаба, волна, скорость
    tower-panel/  # выбранная башня: апгрейд, продажа, ранг, статы
    build-menu/   # выбор башни для постройки (на мобильных — bottom sheet)
    result-dialog/
  features/
    place-tower/
    upgrade-tower/
    sell-tower/
    start-wave/       # досрочный вызов волны с бонусом
    game-speed/
    camera-controls/  # пан/зум: мышь, колесо, pinch
  entities/
    battle/       # агрегат мира: состояние, тик, команды, события
    tower/        # типы, статы по уровням, ранги, выбор цели, view-фабрика
    enemy/        # типы, броня, движение по пути, view-фабрика
    projectile/
    wave/         # описание волн и спавнер
    level/        # загрузка Tiled-карты, путь, buildable-клетки
    progress/     # сохранения и настройки (localStorage, версия схемы)
  shared/
    lib/sim/      # fixed-step цикл, ГСЧ, типизированный event emitter
    lib/iso/      # проекция «клетка ↔ экран»
    lib/debug/    # debug-оверлей, логгер, window.__game (только dev/test)
    ui/           # базовые Vue-компоненты (Button, Panel, Icon)
    i18n/         # словарь RU
    config/       # константы движка (размер тайла, tick rate)
```

**Связи между сущностями.** `entities/battle` — агрегат: ему нужны tower, enemy, projectile, wave и level. Это пересечение импортов внутри одного слоя, поэтому оно идёт только через FSD-нотацию `@x`: например, `entities/tower/@x/battle.ts`. Других пересечений между сущностями нет. Фичи вызывают команды `battle`, виджеты рендерят.

**Сегменты внутри слайса:** `model/` (чистая логика и типы), `config/` (данные баланса как типизированные TS-константы), `view/` (Phaser-объекты), `ui/` (Vue-компоненты), `lib/`. В `model/` нельзя импортировать `phaser` и `vue` — это проверяет ESLint (`no-restricted-imports`).

### 3.3 Состояние и сохранения

- Состояние боя живёт только в симуляции. Pinia хранит производные для UI и сессионные настройки.
- `entities/progress` хранит в `localStorage` ключ `vdgd:save:v1`: `{ version, levels: { [id]: { stars, bestHp } }, settings: { volume, music, sfx, showRanges } }`. Если версия неизвестна или JSON битый, берём дефолт и пишем предупреждение в лог. Игра не должна падать.
- Пауза включается автоматически на `visibilitychange` и `blur`.

### 3.4 Ошибки

- Ассет не загрузился → экран ошибки с кнопкой «Повторить». Сама игра не зависает.
- Необработанное исключение в симуляции или сцене → бой ставится на паузу, показывается экран «Что-то пошло не так» с кнопкой «Скопировать отчёт»: seed, реплей, user agent, стек.
- `localStorage` недоступен (приватный режим) → игра работает без сохранений и один раз об этом предупреждает.

## 4. Геймплей

### 4.1 Цикл боя

1. Подготовка: на старте у игрока 600 кредитов, ставит башни.
2. Волна: враги выходят из точки спавна и идут по пути к штабу.
3. Если враг дошёл до штаба, штаб теряет `leak`-урон этого врага. Прочность штаба — 20.
4. Между волнами пауза 15 с. Можно вызвать следующую волну досрочно: бонус равен 1 кредиту за каждую оставшуюся секунду × номер волны.
5. Победа — пережить 12 волн. Поражение — прочность штаба 0.
6. Звёзды: 3 при HP ≥ 18, 2 при HP ≥ 10, 1 при HP > 0.
7. Меню паузы: «Продолжить», «Начать заново», «Настройки», «Выйти в меню». Выход посреди боя спрашивает подтверждение.

**Карта MVP:** изометрическая сетка около 24×24 клеток, пустынная база. Один вход, один путь с 3–4 поворотами и длинной петлёй вокруг центральной высоты — это лучшее место для миномёта. Около 40 buildable-клеток. Штаб стоит в противоположном углу от входа.

**Обучение при первом запуске:** короткие подсказки поверх игры — «поставь башню», «начни волну», «улучши башню», «посмотри на ранг». Их можно пропустить; флаг «пройдено» хранится в сохранении.

### 4.2 Урон и броня (как в Generals)

Урон считается так: `база × модификатор[тип урона][тип брони] × бонус ранга`.

| Урон \ Броня | Пехота | Лёгкая техника | Танк | Воздух |
|---|---|---|---|---|
| Пулемёт | 1.0 | 0.6 | 0.25 | 0.75 |
| Ракета | 0.4 | 1.0 | 1.25 | 1.0 |
| Фугас (сплэш) | 1.25 | 0.8 | 0.6 | 0 |
| ПВО | 0 | 0 | 0 | 1.5 |

### 4.3 Башни игрока («Коалиция»)

У каждой башни 3 уровня. Продажа возвращает 70% всех вложенных денег.

| Башня | Цена | Урон | Цели | Роль |
|---|---|---|---|---|
| Пулемётное гнездо | 100 | Пулемёт | земля + воздух | Дешёвая, скорострельная, против пехоты |
| Ракетный расчёт | 175 | Ракета | земля + воздух | Против техники |
| Миномётная батарея | 250 | Фугас, радиус 1.5 клетки | только земля, мёртвая зона 1.5 клетки | Против толп |
| Зенитный комплекс | 200 | ПВО | только воздух | Против дронов |

Конкретные числа (урон, скорострельность, дальность, цены апгрейдов) лежат в `entities/tower/config` и подбираются балансным тестом (§6.4).

**Выбор цели:** по умолчанию — враг, который дальше всех продвинулся по пути. На десктопе приоритет переключается из панели башни: первый, сильнейший или ближайший.

### 4.4 Ранги ветеранства

За убийство башня получает опыт, равный награде за врага.

| Ранг | Опыт | Бонус |
|---|---|---|
| Рядовой | 0 | — |
| Ветеран | 150 | урон +10% |
| Элита | 400 | урон +20%, скорострельность +10% |
| Герой | 900 | урон +35%, скорострельность +20%, дальность +10% |

Ранг показывается шевронами над башней. При продаже ранг теряется. Апгрейд ранг не сбрасывает.

### 4.5 Враги («Фронт освобождения»)

| Враг | Броня | Особенность |
|---|---|---|
| Боевик | Пехота | Базовый, идёт группами |
| Гранатомётчик | Пехота | Больше HP, медленный |
| Техничка | Лёгкая техника | Быстрая |
| Танк «Скорпион» | Танк | Много HP, медленный |
| Дрон-камикадзе | Воздух | Летит по пути, по нему бьют только башни, умеющие стрелять по воздуху |
| Босс «Мародёр» (волна 12) | Танк | Очень много HP; когда HP падает ниже 50%, выпускает 4 боевиков |

### 4.6 Управление

| Действие | Десктоп | Мобильные |
|---|---|---|
| Выбрать башню для постройки | клавиши `1`–`4` или меню | тап по иконке в нижней панели |
| Поставить | клик по подсвеченной клетке | тап по клетке → ghost-превью → кнопка «Построить» |
| Выбрать башню | клик | тап |
| Апгрейд / продажа | `U` / `S` / панель | панель (bottom sheet) |
| Отмена | `Esc` / ПКМ | тап мимо |
| Камера | WASD / край экрана / колесо | drag / pinch |
| Следующая волна | `Space` | кнопка |
| Пауза / скорость | `P` / `F` | кнопки |

Мобильные: только альбомная ориентация, в портретной показываем подсказку повернуть экран. Тач-зоны не меньше 44×44 px, кнопки HUD учитывают safe-area.

## 5. Ассеты

- Источники: Kenney.nl и OpenGameArt, только CC0 (или CC-BY с указанием авторов). Каждый файл записываем в `public/assets/LICENSES.md`: источник, автор, лицензия.
- Пока ассетов нет, `view/`-фабрики рисуют заглушки через `Phaser.GameObjects.Graphics`: ромбы клеток, цветные фигуры, разные для каждого типа. Игра должна полностью работать на заглушках.
- Спрайты собираем в атласы (TexturePacker-совместимый JSON). Звуки — `ogg` + `m4a`.
- Карту рисуем в Tiled, исходник лежит в `public/assets/maps/`.

## 6. Тестирование и критерии качества

### 6.1 Definition of Done для любой задачи

Все команды должны проходить без ошибок:

```
npm run typecheck   # vue-tsc --noEmit
npm run lint        # eslint
npm run lint:fsd    # steiger ./src — информативно, не блокирует
npm run test        # vitest run
npm run e2e         # playwright, обязательно если менялись UI, ввод или сцены
```

Новая логика в `model/` сдаётся вместе с тестами. Исправленный баг — вместе с регресс-тестом, который до фикса падал.

### 6.2 Unit-тесты (Vitest, без браузера)

- Матрица урона и брони, бонусы рангов, пороги опыта, расчёт возврата при продаже.
- Движение врага по пути с учётом скорости и тиков; утечка в штаб.
- Выбор цели для каждого приоритета, мёртвая зона миномёта, правило «ПВО только по воздуху».
- Экономика: награда за убийство, бонус досрочной волны, нельзя уйти в минус.
- Спавнер волн: состав и тайминги совпадают с конфигом.
- `progress`: миграция и восстановление после битого JSON.
- Покрытие `entities/**/model` и `shared/lib/**` — не ниже 80% строк.

### 6.3 Детерминизм и реплеи

- **Тест детерминизма:** один и тот же seed и список команд, два прогона → одинаковый хэш состояния на каждом сотом тике.
- **Golden-реплеи:** в `tests/replays/*.json` лежат записанные партии (`{ seed, levelId, commands: [{tick, cmd}] }`). Тест проигрывает реплей headless и сверяет снапшот итогового состояния. Если снапшот изменился из-за баланса — обновляем осознанно, с объяснением в PR.

### 6.4 Балансные тесты

Headless-прогоны всей карты на x∞, тест занимает меньше 5 с:

- **Без башен** — поражение не позже волны 3.
- **Эталонная стратегия** (скриптовый бот: фиксированная расстановка и апгрейды) — победа с HP ≥ 10.
- **Только пулемёты** — поражение на волне с дронами и танками, то есть монострой не проходит карту.
- **Нижняя граница:** 50 случайных ботов с разными seed — доля побед в диапазоне 20–80%. Это значит, что карта не тривиальна и не невозможна.

### 6.5 E2E (Playwright)

Проекты: `desktop-chromium`, `mobile` (эмуляция Pixel 7, альбомная ориентация, `hasTouch`) и `mobile-safari` (WebKit, эмуляция iPhone 14, альбомная ориентация).

**Как запускать:**

- `npm run e2e` — headless; так тесты гоняются в CI и при обычной проверке.
- `npm run e2e:headed` (`playwright test --headed --workers=1`) — тесты идут в видимом окне браузера по одному, видно каждое действие.
- `npm run e2e:ui` (`playwright test --ui`) — UI-режим Playwright: тайм-лайн, шаги, DOM-снимки, повтор теста.
- При падении сохраняются trace, видео и скриншот (`retain-on-failure`). Посмотреть: `npx playwright show-trace`.
- **Ручная проверка через агента:** Claude открывает игру в видимом окне через Playwright MCP (dev-сервер `npm run dev`), проходит сценарий, делает скриншоты и читает консоль. Так `qa-debugger` воспроизводит баги, которые описаны словами, ещё до того, как написан тест.

1. **Смоук:** главное меню → «Играть» → канвас отрисован, в консоли нет ошибок.
2. **Постройка:** выбрать башню → поставить на buildable-клетку → деньги уменьшились, башня есть в `__game.state`. На небилдабельной клетке постройка запрещена.
3. **Апгрейд и продажа** через панель.
4. **Полный бой:** через `__game` выдать деньги и ускорить до x8 → победа → экран результата → звёзды сохранились после перезагрузки.
5. **Мобильный:** тап → превью → «Построить», pinch-зум не ломает выбор клетки, подсказка про портретную ориентацию.
6. **Пауза на blur:** после `page.evaluate(() => dispatchEvent(new Event('blur')))` тик симуляции не растёт.

Тесты управляют игрой и проверяют её через `window.__game`. Этот объект есть только при `import.meta.env.DEV || MODE === 'test'`, в продакшн-сборку не попадает — это проверяется тестом на бандл.

### 6.6 Производительность

| Сценарий | Десктоп | Мобильные (средний Android) |
|---|---|---|
| 150 врагов + 40 башен + снаряды | ≥ 60 FPS | ≥ 30 FPS |
| Время до интерактива (prod build) | < 3 с | < 5 с на 4G |
| Память после 3 рестартов боя | без роста > 10% | то же |

Для проверки есть стресс-сцена `?debug=1&stress=1`. Снаряды и эффекты берутся из пулов объектов. При выходе со страницы боя вызывается `Phaser.Game.destroy(true)`.

## 7. Отладка

- **Debug-оверлей** (`F3` или `?debug=1`): FPS, номер тика, число сущностей, сетка клеток, buildable-маска, путь, радиусы всех башен, текущая цель каждой башни.
- **Параметры URL:** `?seed=123` (фиксированный ГСЧ), `?wave=8` (начать с волны), `?money=9999`, `?speed=8`.
- **Пошаговый режим:** на паузе клавиша `.` продвигает симуляцию на 1 тик.
- **`window.__game`** (только dev/test): `state`, `dispatch(cmd)`, `step(n)`, `setSpeed(x)`, `exportReplay()`, `loadReplay(json)`.
- **Логгер** `shared/lib/debug/logger`: уровни и теги (`sim`, `render`, `input`, `save`). В prod остаются только `warn` и `error`.
- **Порядок работы с багом:** воспроизвести → `exportReplay()` → положить реплей в `tests/replays/bugs/` → написать падающий тест → исправить → тест зелёный.
- Инструменты: Vue Devtools (Pinia), Chrome Performance для просадок FPS, Memory snapshots для утечек.

## 8. Субагенты для реализации

Файлы агентов лежат в `.claude/agents/`. Основная сессия Claude Code — оркестратор: разбивает этап на задачи, раздаёт их агентам и принимает результат по Definition of Done (§6.1).

| Агент | Зона ответственности | Пишет код в | Инструменты |
|---|---|---|---|
| `sim-engineer` | Симуляция: тик, команды, бой, экономика, волны, ранги | `entities/*/model`, `entities/*/config`, `shared/lib/sim` | read/write/bash |
| `render-engineer` | Phaser: сцены, изометрия, спрайты, анимации, ввод, камера, тач | `entities/*/view`, `widgets/battlefield`, `features/camera-controls`, `shared/lib/iso` | read/write/bash |
| `ui-engineer` | Vue: страницы, HUD, панели, меню, сторы, i18n, сохранения | `pages`, `widgets/*/ui`, `features/*/ui`, `shared/ui`, `entities/progress` | read/write/bash |
| `balance-designer` | Числа: статы, волны, цены; балансные тесты | `entities/*/config`, `tests/balance` | read/write/bash |
| `qa-debugger` | E2E, воспроизведение багов, реплеи, перф-замеры, отчёты | `tests/`, `e2e/` (продуктовый код не меняет) | read/write/bash |

Правила взаимодействия:

- Изменения, которые затрагивают зоны двух агентов (например, новая команда симуляции и кнопка в UI), делаем последовательно: сначала `sim-engineer` фиксирует контракт команды или события и тест, потом `ui-engineer` или `render-engineer`.
- После каждого этапа `qa-debugger` прогоняет весь DoD. Строгость FSD на стадии MVP не приоритет.
- Агенты не добавляют зависимости без согласования с оркестратором.

## 10. Открытые вопросы

- Доступность: нужна ли палитра для дальтоников (различать типы врагов не только цветом) и ремаппинг клавиш.
- Музыка и озвучка юнитов («реплики» в духе Generals) — бесплатные CC0-реплики найти трудно, возможно, понадобится TTS или актёр.

- Сюжетная обёртка и названия карт.
- Нужна ли в будущем вторая фракция игрока — от этого зависит, выносить ли конфиги башен в отдельный слайс `faction`.
