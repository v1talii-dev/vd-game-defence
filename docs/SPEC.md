# Спецификация: браузерный Tower Defense в стиле Generals: Zero Hour

Статус: черновик v0.2 · 2026-10-22 (переход на 3D — §3.5, §4.7, этап M7)

## 1. Цели и рамки

**Что делаем:** классический tower defense в браузере. 3D-сцена с камерой под изометрическим углом, военный сеттинг в духе Command & Conquer: Generals — Zero Hour (типы урона против типов брони, ранги ветеранства, «пустынная» эстетика).

**MVP — вертикальный срез:** одна карта, сделанная полностью и с хорошим качеством, чтобы проверить, интересна ли сама игра.

| Параметр | Решение |
|---|---|
| Графика | 3D (Three.js), камера под изо-углом. Модели пока из примитивов, снаряды летят по видимым траекториям |
| Механика | Классический TD: фиксированный путь врагов, башни ставятся на разрешённые клетки, деньги за убийства |
| Режимы | Только одиночная игра, без бэкенда |
| Фракции | 1 у игрока («Коалиция») и 1 у врага («Фронт освобождения»), обе вымышленные |
| Фичи сверх базы | Апгрейды башен (3 уровня) и ранги ветеранства |
| Платформы | Десктоп (мышь + горячие клавиши) и мобильные (тач) |
| Язык | Только RU, но все строки лежат в отдельном словаре |
| Ассеты | Бесплатные паки CC0 (Kenney, OpenGameArt). Пока их нет — процедурные заглушки |

**Вне рамок MVP:** вторая и последующие карты, кампания (план — §4.8 и CONCEPT.md, с M12), генеральские способности, бесконечный режим (отменён), мультиплеер, собственные юниты игрока, редактор карт.

**Юридическое:** ничего не берём из Generals — ни ассетов, ни звуков, ни названий юнитов и фракций, ни логотипов. Используем только жанр и стилистику.

## 3. Архитектура

### 3.1 Главный принцип: симуляция отделена от рендера

```
          команды (place/upgrade/sell/startWave/setSpeed)
 Vue UI ───────────────────────────────┐
   ▲                                   ▼
   │ события (throttle)       ┌──────────────────┐
   └──────────────────────────│  Симуляция (TS)  │  чистый TS, без Phaser и DOM
                              │  fixed tick 30 Гц│  детерминирована: seed + команды
   3D-сцена   ◄─ читает ────└──────────────────┘
   (Three.js: рендер, интерполяция,
    ввод → команды)
```

- **Симуляция** — чистый TypeScript без импортов Three.js, Vue и DOM. Фиксированный шаг 30 тиков/с, собственный ГСЧ с seed. Одинаковые seed и список команд всегда дают одинаковое состояние: на этом держатся тесты, реплеи и отладка. Координаты в симуляции 3D: `x, y` — клетки на плоскости карты, `z` — высота в клетках (§4.7).
- **3D-сцена** только рисует: каждый кадр читает состояние симуляции, синхронизирует меши и интерполирует позиции (включая `z`) между тиками. Ввод превращает в команды.
- **Vue** рисует HUD и меню. Подписывается на события симуляции (`moneyChanged`, `waveStarted`, `towerSelected`…) через Pinia-стор и не опрашивает состояние каждый кадр.
- Скорость игры (пауза / x1 / x2) — это число тиков симуляции за кадр. В тестах доступна x8 и пошаговый режим.

### 3.2 Слои FSD

Импорты разрешены только сверху вниз: `app → pages → widgets → features → entities → shared`. Каждый слайс отдаёт наружу только свой `index.ts` (public API).

```
src/
  app/            # точка входа, роутер, Pinia, глобальные стили, провайдеры
  pages/
    main-menu/
    battle/       # страница боя: собирает виджеты
    settings/
  widgets/
    battlefield/  # монтирует WebGL-рендерер и 3D-сцену, мост ввод → команды
    hud/          # деньги, прочность штаба, волна, скорость
    tower-panel/  # выбранная башня: апгрейд, продажа, ранг, статы
    build-menu/   # выбор башни для постройки (на мобильных — bottom sheet)
    result-dialog/
  features/
    place-tower/
    upgrade-tower/
    sell-tower/
    start-wave/       # досрочный вызов волны с бонусом
    game-speed/
    camera-controls/  # пан/зум: мышь, колесо, pinch
  entities/
    battle/       # агрегат мира: состояние, тик, команды, события
    tower/        # типы, статы по уровням, ранги, выбор цели, view-фабрика
    enemy/        # типы, броня, движение по пути, view-фабрика
    projectile/
    wave/         # описание волн и спавнер
    level/        # загрузка Tiled-карты, путь, buildable-клетки
    progress/     # сохранения и настройки (localStorage, версия схемы)
  shared/
    lib/sim/      # fixed-step цикл, ГСЧ, event emitter, vec3, траектории снарядов
    lib/three/    # рендерер, риг камеры, пикинг «экран → клетка», пулы мешей
    lib/debug/    # debug-оверлей, логгер, window.__game (только dev/test)
    ui/           # базовые Vue-компоненты (Button, Panel, Icon)
    i18n/         # словарь RU
    config/       # константы движка (размер тайла, tick rate)
```

**Связи между сущностями.** `entities/battle` — агрегат: ему нужны tower, enemy, projectile, wave и level. Это пересечение импортов внутри одного слоя, поэтому оно идёт только через FSD-нотацию `@x`: например, `entities/tower/@x/battle.ts`. Других пересечений между сущностями нет. Фичи вызывают команды `battle`, виджеты рендерят.

**Сегменты внутри слайса:** `model/` (чистая логика и типы), `config/` (данные баланса как типизированные TS-константы), `view/` (3D-объекты Three.js), `ui/` (Vue-компоненты), `lib/`. В `model/` нельзя импортировать `three` и `vue` — это проверяет ESLint (`no-restricted-imports`).

### 3.3 Состояние и сохранения

- Состояние боя живёт только в симуляции. Pinia хранит производные для UI и сессионные настройки.
- `entities/progress` хранит в `localStorage` ключ `vdgd:save:v2` (M12; до этого `vdgd:save:v1`): `{ version: 2, levels: { [id]: { stars, bestHp, bestTick? } }, settings: { volume, sfx, showRanges }, tutorialDone, helpHintSeen }`. Миграция: если `v2` нет, читается `v1` (все поля переносятся как есть, `version` становится 2), результат записывается в `v2`, ключ `v1` не удаляется (откат безопасен). Если версия неизвестна или JSON битый, берём дефолт и пишем предупреждение в лог. Игра не должна падать. Разблокировки уровней и башен вычисляются из `levels` (§4.8), отдельно не хранятся.
- Пауза включается автоматически на `visibilitychange` и `blur`.

### 3.4 Ошибки

- Ассет не загрузился → экран ошибки с кнопкой «Повторить». Сама игра не зависает.
- Необработанное исключение в симуляции или сцене → бой ставится на паузу, показывается экран «Что-то пошло не так» с кнопкой «Скопировать отчёт»: seed, реплей, user agent, стек.
- `localStorage` недоступен (приватный режим) → игра работает без сохранений и один раз об этом предупреждает.
- WebGL недоступен или контекст потерян (`webglcontextlost`) → пауза и экран с кнопкой «Перезапустить бой». Состояние симуляции при этом не теряется.

### 3.5 3D-рендер

Принцип: **простая геометрия, честная картинка траекторий**. Модели и карту потом улучшаем точечно, не трогая симуляцию.

- **Сцена:** ось `x` и ось `y` клетки соответствуют мировым `x` и `z` Three.js, высота `z` соответствует мировой `y`. Одна клетка — 1 единица мира. Пересчёт живёт в одном месте, в `shared/lib/three`.
- **Камера:** перспективная, узкий FOV (около 30°), смотрит сверху под углом около 50°, по умолчанию с поворотом 45° — так картинка похожа на прежнюю изометрию. Пан и зум с ограничением по краям карты. Поворота камеры нет: угол фиксирован. Мобильные в M7 не поддерживаем (как и раньше — отложены); когда вернёмся к ним — фиксированный угол, пан и pinch.
- **Карта:** строится из данных уровня. Дорога занимает ровно клетки пути: в точке входа начинается на краю карты (не выступает за него), у штаба доходит до края карты по направлению движения, на поворотах углы закрыты. Клетки — плоские квадраты с цветом по типу (песок, дорога, buildable). Плато — коробка. Декор — примитивы (ящики, конусы-камни) в точках из Tiled. Свет: один направленный и один ambient. Реальные тени выключены, под врагами рисуется круглая тень-«блоб» (один InstancedMesh); у снарядов теней нет.
- **Модели-заглушки** (фабрики в `entities/*/view`): башня — цилиндр-основание и поворотная «голова» со стволом, которая смотрит на цель; враги — капсулы (пехота), коробки (техника), коробка с башней (танк), плоский ромб на высоте (дрон). Цвет и силуэт свои у каждого типа.
- **Снаряды:** мелкие меши (сфера, конус-ракета) с ориентацией по вектору скорости. За ракетами и минами тянется след (лента из последних N позиций). Вспышка выстрела, взрыв — расширяющаяся сфера и частицы-billboard'ы.
- **Башни в процессе (очередь, стройка, улучшение):** модель всегда рисуется целиком, в нормальных пропорциях, без масштабирования по высоте. Состояние читается по кольцу над башней (см. правило индикаторов): стройка и улучшение — заливка кольца по часовой, цвета разные, без полосок. Запланированная (в очереди, оплаты ещё нет) башня — та же модель, но с подсветкой «ещё не построена»: полупрозрачная голограмма с кольцом в состоянии «ожидание». Запланированное улучшение показывается тем же кольцом «ожидание» над действующей башней. Прогресс интерполируется между тиками.
- **Анимация ходьбы пехоты:** у пехоты (боевик, гранатомётчик) ноги двигаются при движении: шаг попеременно, фаза зависит от пройденного пути (без «скольжения»), на месте ноги стоят. Реализация процедурная: ноги — отдельные части модели, качаются вокруг бедра в рендере, без скелета и без влияния на симуляцию; InstancedMesh сохраняется.
- **Над объектами:** полоски HP врагов, шевроны ранга и кольца прогресса башен — billboard'ы, которые всегда повёрнуты к камере. Радиус башни — кольцо на земле.
- **Правило индикаторов:** одно компактное **кольцо-билборд над башней** (≈0.7 клетки, рисуется поверх геометрии, модель не закрывает его; центр пустой, тонкая белая обводка ≈10% радиуса, незаполненная часть — лёгкая тёмная полупрозрачная заливка). Состояния: «ожидание» (заказ постройки или улучшения ждёт кредитов) — тусклое кольцо с бегущим светлым сегментом; «стройка» (0xffe14d) и «улучшение» (0x3dd6ff) — заливка по часовой стрелке от верха, по заливке видно, сколько осталось (цифр нет). Рамка по кромке плато была отвергнута: модель закрывает её часть и неочевидно, сколько осталось. Шевроны ранга остаются отдельными значками. Новый индикатор вводится только по этому правилу.
- **Кадр карты:** при входе в бой карта заполняет экран (стартовый zoom подбирается по размеру вьюпорта и карты, без больших пустых полей). Чёрной пустоты за краями карты нигде не видно: земля продолжается за границу (внешнее «поле» тоном темнее карты, с лёгким туманом к горизонту), цвет фона совпадает с дальним краем тумана. Пан и минимальный zoom ограничены так, что в кадр не попадает край внешнего поля. Число и размер внешнего поля — константы в `shared/lib/three`.
- **Производительность:** однотипные объекты рисуются через `InstancedMesh` или пул мешей; материалы и геометрии общие и создаются один раз. `devicePixelRatio` не больше 2, на мобильных не больше 1.5. При уходе со страницы боя вызываются `renderer.dispose()` и `dispose()` у геометрий и материалов.
- **Ввод:** клик или тап превращается в луч, который пересекается с плоскостью земли, и получаем клетку. Выбор башни или врага — raycast по их хитбоксам.
- **PICK (хитбоксы выбора):** вертикальные цилиндры вокруг основания, побеждает ближайший к камере. Башня — радиус 0.8 клетки (тач 1.0), высота не меньше 1.4 (модели крупнее ~1.2–1.4). Враг — радиус 0.55 (тач +0.4), высота по высоте модели. Константы в `shared/lib/three/pick.ts`. В режиме постройки башня выбирается только по своей клетке (на таче — ещё и по PICK), поэтому цилиндр соседней башни не мешает ставить башню на соседнюю клетку; ghost-превью следует за точной клеткой под курсором.
- **HP башен и руины (M13b):** над башней с HP < 100% и над выбранной — billboard-полоска HP (зелёная, жёлтая, красная), общий InstancedMesh с полосками врагов или тот же приём, без аллокаций в кадре. Это единственное исключение из правила индикаторов: HP — величина, а не состояние; рамка по кромке плато остаётся для состояний «ожидание/стройка/улучшение». Руины — приплюснутая тёмная модель на плато вместо башни; выстрел врага — меш снаряда `shell` по §4.7; попадание — маленькая вспышка из пула.
- **Стрелки пути (M13):** короткая анимация маршрута: в начале боя и при старте каждой волны по пути от входа к штабу пробегают бегущие шевроны-стрелки по земле, длительность 2–3 с, затем гаснут; при нескольких входах и развилках показывается каждый маршрут. Только рендер (по `roadSegments`), без влияния на симуляцию; общий инстанс-меш, без аллокаций в кадре; в `prefers-reduced-motion` — статичный показ.
- **Hover (мышь):** над башней или врагом курсор `pointer` и тонкое кольцо на земле (для башни — радиус стрельбы), без аллокаций в кадре.

## 4. Геймплей

### 4.1 Цикл боя

1. Подготовка: на старте у игрока 600 кредитов, ставит башни.
2. Волна: враги выходят из точки спавна и идут по пути к штабу.
3. Если враг дошёл до штаба, штаб теряет `leak`-урон этого врага. Прочность штаба — 20.
4. Между волнами пауза 15 с. Можно вызвать следующую волну досрочно: бонус равен 1 кредиту за каждую оставшуюся секунду × номер волны.
5. Победа — пережить 12 волн. Поражение — прочность штаба 0.
6. Звёзды: 3 при HP ≥ 18, 2 при HP ≥ 10, 1 при HP > 0.
7. Меню паузы: «Продолжить», «Начать заново», «Настройки», «Выйти в меню». Выход посреди боя спрашивает подтверждение.

**Карта MVP:** изометрическая сетка около 24×24 клеток, пустынная база. Один вход, один путь с 3–4 поворотами и длинной петлёй вокруг центральной высоты — это лучшее место для ракетных расчётов. Около 40 buildable-клеток. Штаб стоит в противоположном углу от входа.

**Обучение при первом запуске:** короткие подсказки поверх игры — «поставь башню», «начни волну», «улучши башню», «посмотри на ранг». Их можно пропустить; флаг «пройдено» хранится в сохранении.

### 4.2 Урон и броня (как в Generals)

Урон считается так: `база × модификатор[тип урона][тип брони] × бонус ранга`.

| Урон \ Броня | Пехота | Лёгкая техника | Танк | Воздух |
|---|---|---|---|---|
| Пулемёт | 1.0 | 0.6 | 0.25 | 0.75 |
| Ракета | 0.4 | 1.0 | 1.25 | 1.0 |

### 4.3 Башни игрока («Коалиция»)

У каждой башни 3 уровня. Продажа возвращает 70% всех вложенных денег.

**Очередь и время постройки.** Если денег на башню не хватает, команда `buildTower` не отклоняется: заказ ставится в очередь на выбранную клетку (клетка занята, башня-призрак с отметкой «ждёт кредитов»). Деньги списываются, как только их хватает, по порядку заказов (FIFO; пока первый заказ не оплачен, следующие не оплачиваются). После оплаты башня строится `buildSeconds` (из `entities/tower/config`, стартово 2 с пулемёт и 3 с ракета, подбирает balance-designer) и не стреляет; по завершении становится обычной башней. Заказ можно отменить: неоплаченный — без потерь, оплаченный и строящийся — возврат 100%.

**Бесплатная отмена (M13).** Построенную башню можно продать с возвратом 100% всех вложений (включая улучшения), если выполнено любое из условий: (а) идёт фаза подготовки — волна не идёт (до первой волны и в паузах между волнами); (б) с момента оплаты башни прошло не больше `FREE_REFUND_SECONDS` (стартово 5 с, константа в `entities/tower/config`, считается в тиках от `paidTick`, детерминированно). Иначе продажа — 70%. Решение пользователя 2026-10-23; точное N подбирает balance-designer. Прогресс стройки показывается так же, как у улучшения. События: `towerOrdered`, `towerBuildStarted`, `towerBuilt`, `towerBuildCancelled`. Продажа строящейся башни — это отмена. Остальные правила (цены, ранги, продажа 70%) без изменений. Это решение оркестратора по умолчанию, пользователь может его пересмотреть.

**Запланированное улучшение.** Если денег на улучшение не хватает (или впереди есть неоплаченные заказы), `upgradeTower` не отклоняется: улучшение ставится в ту же общую очередь, что и заказы построек, и оплачивается строго FIFO по моменту заказа (пока первый заказ любого вида не оплачен, следующие ждут). Башня в ожидании остаётся `active`: стреляет, набирает опыт, продаётся. После оплаты начинается обычное улучшение (`towerUpgradeStarted`, списание в этот момент). Повторный `upgradeTower` по башне с заказом отклоняется (`alreadyUpgrading`). Отмена — `cancelUpgrade` (без списаний, возврат 0); та же клавиша и кнопка «Отмена», что и при улучшении. Продажа башни с запланированным улучшением сначала снимает заказ (без возвратов, событие `towerUpgradeCancelled` с `refund: 0`), затем продаёт обычным порядком (70% от вложенного). Новые события: `towerUpgradeOrdered { towerId, toLevel, cost, waiting }`. Порядок очереди задаётся номером заказа из общего счётчика `nextId`, поэтому реплеи детерминированы. Индикатор в 3D — компактное кольцо «ждёт кредитов» (§3.5), на панели — «Улучшение в очереди» и «Отмена». Решение по умолчанию, пользователь может пересмотреть.

**Прогресс стройки и улучшения** показывается кругом (кольцом) над башней, а не полоской (§3.5).

**Время улучшения.** Улучшение не мгновенное: после команды `upgradeTower` деньги списываются сразу, а башня переходит в состояние «улучшается» на `upgradeSeconds` (из `entities/tower/config`, растёт с уровнем: стартово 3 с на уровень 2 и 5 с на уровень 3, окончательно подбирает balance-designer). Во время улучшения башня не стреляет и не набирает опыт; новые статы применяются в тик завершения, ранг и опыт сохраняются. Отмена (`cancelUpgrade`) возвращает 100% цены улучшения и сбрасывает прогресс. Продажа во время улучшения недоступна. Прогресс (`upgradeProgress` 0..1, считается в тиках) показывается кольцом над башней в 3D (§3.5) и на панели выбранной башни (вместо «Улучшить» — «Отмена» и секунды). События симуляции: `towerUpgradeStarted`, `towerUpgradeCancelled`, `towerUpgraded`.

| Башня | Цена | Урон | Цели | Роль |
|---|---|---|---|---|
| Пулемётное гнездо | 100 | Пулемёт | земля + воздух | Дешёвая, скорострельная, против пехоты |
| Ракетный расчёт | 175 | Ракета | земля + воздух | Против техники |

**Урон по башням, ремонт и руины (M13b).** Решение пользователя 2026-10-23: башни могут быть атакованы врагами (§4.5), их можно чинить, они чинятся сами и самолечатся по рангу (§4.4). Подробности и обоснование — `docs/CONCEPT.md` §10 (рекомендованный вариант; альтернатива — «выведена из строя» без руин, §10.3). Числа — в `entities/tower/config`, ориентир ниже, окончательно подбирает balance-designer.

- **HP.** В `TowerLevelStats` поле `hp` (ориентир: пулемёт 140/180/230, ракета 180/240/300); максимум умножается на `hpMul` ранга, при росте максимума текущее HP растёт на ту же разницу. Завершение улучшения полностью лечит. Башня в состоянии `building` неуязвима и не выбирается целью; в `upgrading` и запланированном улучшении уязвима.
- **Руины.** HP = 0 → башня переходит в состояние `ruins` (событие `towerDestroyed`): не стреляет, не считается целью, клетка занята, опыт и ранг сохраняются. `restoreTower` — стоит `RESTORE_COST_RATIO` (0.6) вложений, ставится заказом в общую FIFO-очередь, строится `buildSeconds`, по завершении башня с полным HP и прежним рангом (`towerRestored`). `clearRuins` — бесплатно, клетка освобождается, опыт и ранг теряются (`ruinsCleared`). Продать руины нельзя.
- **Ручной ремонт.** `repairTower { towerId }`: цена = `REPAIR_COST_RATIO` (0.35) × вложения × (недостающее HP / максимум), округление вверх, минимум 1; списывается сразу, лечение равномерно за `REPAIR_SECONDS` (4 с); башня во время ремонта стреляет. Не хватает денег → `notEnoughMoney` (в очередь не ставится); полное HP, `building`, `ruins` → отклоняется. Повторный ремонт во время ремонта отклоняется (`alreadyRepairing`). Если башню добивают, остаток ремонта сгорает без возврата.
- **Авторемонт вне волны.** Пока волна не идёт (подготовка и паузы), все башни бесплатно лечатся на `AUTO_REPAIR_PER_SEC` (10%) максимума HP в секунду.
- **Продажа** повреждённой башни считает возврат от вложений, а не от HP; правило бесплатной отмены выше не меняется. `sellRefund` в снимке башни остаётся единственным источником суммы для UI.
- **Снимок башни** добавляет `hp`, `maxHp`, `repairProgress` (0..1 или null), `repairCost` (сколько стоит чинить сейчас) и `state: 'ruins'`. События: `towerDamaged { towerId, amount, hp, attackerId }`, `towerDestroyed { towerId, x, y }`, `towerRepairStarted { towerId, cost }`, `towerRestoreOrdered`, `towerRestored`, `ruinsCleared`.
- **Детерминизм.** Лечение и урон по тикам, формулы только `+ − × ÷` и `Math.sqrt`, цель по расстоянию² и `id`, ГСЧ не используется; реплеи пишут `repairTower`, `restoreTower`, `clearRuins` как обычные команды.
- **Индикация (§3.5).** Над башней с HP < 100% или выбранной — billboard-полоска HP (цвет по доле), это явное исключение из правила индикаторов; руины — приплюснутая тёмная модель на плато. Панель башни: HP, кнопка «Чинить» (цена и клавиша `C`), у руин — «Восстановить» и «Убрать».

Конкретные числа (урон, скорострельность, дальность, цены апгрейдов) лежат в `entities/tower/config` и подбираются балансным тестом (§6.4).

**Выбор цели:** по умолчанию — враг, который дальше всех продвинулся по пути. На десктопе приоритет переключается из панели башни: первый, сильнейший или ближайший.

### 4.4 Ранги ветеранства

За убийство башня получает опыт, равный награде за врага.

| Ранг | Опыт | Бонус |
|---|---|---|
| Рядовой | 0 | — |
| Ветеран | 150 | урон +10% |
| Элита | 400 | урон +20%, скорострельность +10% |
| Герой | 900 | урон +35%, скорострельность +20%, дальность +10% |

Ранг показывается шевронами над башней. При продаже ранг теряется. Апгрейд ранг не сбрасывает.

**Живучесть по рангу (M13b).** Ранг также влияет на HP башни (§4.3): максимум HP ×1 / ×1.1 / ×1.25 / ×1.4 (Рядовой / Ветеран / Элита / Герой) и самолечение 0 / 0.5% / 1% / 2% максимума HP в секунду, всегда (в бою тоже). Числа — в `RANKS` (`hpMul`, `regenPerSec`), окончательно подбирает balance-designer. Разрушение башни ранг и опыт не сбрасывает (руины хранят их до восстановления).

### 4.7 Снаряды и траектории

Физика **визуальная**: снаряд летит по правдоподобной траектории, но всегда попадает. Урон наносится в момент прилёта, а не в момент выстрела — поэтому время полёта влияет на бой, а остальной баланс почти не меняется. Траектории считает симуляция (а не рендер): они детерминированы, и рендер только интерполирует их между тиками.

**Модель.** Снаряд хранит точку вылета `from` (x, y, z — дуло башни), прогресс `t ∈ [0, 1]` и цель. Каждый тик `t` растёт на `speed / TICK_RATE / дистанция_при_выстреле`. Позиция считается из `t`:

```
aim(t)  = текущая точка попадания цели (центр хитбокса); если цель погибла — последняя известная
pos.xy  = lerp(from.xy, aim.xy, ease(t))
pos.z   = lerp(from.z, aim.z, ease(t)) + arc · 4t(1 − t)
```

`arc` — высота дуги, `ease` — профиль скорости. При `t = 1` снаряд в точке `aim`: наносится урон, вылетает событие `projectileImpact { x, y, z, kind, targetId }`.

| Тип | Башня | `arc` | `ease` | Поведение |
|---|---|---|---|---|
| `bullet` | Пулемёт | 0 | линейный | Быстрая прямая, трассер |
| `rocket` | Ракетный расчёт | 0.3·дистанции | разгон (`t²`) | Взлёт с дугой и разгоном к цели |
| `shell` (M13b) | Гранатомётчик, танк, босс | 0.15·дистанции | линейный | Снаряд врага по башне; цель разрушена в полёте — снаряд пропадает без урона |

- **Высоты:** земля в симуляции плоская, `z = 0` (плато только рисуется). Наземные враги стоят на `z = 0`, хитбокс задан высотой из конфига; дроны летят на `z = 1.5`. Дуло башни — `muzzleHeight` из конфига башни.
- **Если цель погибла в полёте:** `bullet` и `rocket` долетают до последней известной точки и исчезают без урона.
- **Конфиг:** у башни в `entities/tower/config` есть блок `projectile: { kind, speed, arcFactor, minArc }` и `muzzleHeight`. У врага в `entities/enemy/config` есть `hitHeight` и `flightHeight`.
- **Детерминизм:** в формулах только `+ − × ÷` и `Math.sqrt`. Тригонометрию в симуляции не используем — направления считаем векторами (`shared/lib/sim/vec3`). Повороты голов башен, ориентацию снарядов и следы считает рендер.
- **Будущее (не в M7):** честная баллистика с промахами, попадание по случайным врагам, рельеф и высоты клеток. Модель выше выбрана так, чтобы её можно было заменить на интегрирование скорости, не меняя рендер и события.

### 4.8 Кампания и уровни (M12)

Концепция и решения — `docs/CONCEPT.md`. Рамки: **бесконечного режима нет; враги могут атаковать башни** (решение пользователя 2026-10-23, §4.3–§4.5, M13b; отключений и дебаффов нет); мета-прогрессия — только разблокировки уровней и башен по звёздам; режимы сложности — после кампании (M19).

- **`LevelConfig`** (`entities/level/config/levels.ts`, типизированные TS-константы): `{ id, name, tmj (путь к карте Tiled), waves, startMoney, hqHp, hpScale (по умолчанию 1), allowedTowers: TowerType[], unlocks: TowerType[] (башни, открываемые первым прохождением), requires: { levelId?, stars? } | null, briefing: string[] (2–3 строки, ключи i18n), implemented: boolean }`. Реестр `LEVELS` (порядок = порядок кампании) и `getLevel(id)`; неизвестный id — явная ошибка. Волны переезжают из общего `WAVES` в данные уровня; поведение `desert-base` не меняется (реплеи и балансные тесты зелёные без правок снапшотов).
- **Симуляция** принимает `LevelConfig` целиком: старт, HP штаба, масштаб HP врагов, `allowedTowers` (постройка запрещённой башни — команда отклоняется причиной `towerNotAllowed`). `levelId` уже есть в реплее.
- **Звёзды:** 3 при HP ≥ 18, 2 при HP ≥ 10, 1 при HP > 0 (как §4.1); в сохранении только лучший результат, перепрохождение звёзды не уменьшает.
- **Разблокировки** не хранятся отдельно, а выводятся из `levels` сохранения: уровень открыт, если `requires === null` или в `levels[requires.levelId].stars >= (requires.stars ?? 1)`; башня доступна, если открыта первым уровнем, где она в `unlocks`. Для M12 башни те же (пулемёт, ракета), `unlocks` — пустой.
- **Экран кампании** (`pages/campaign`, маршрут `#/campaign`, заменяет прямую кнопку «Играть» в главном меню): вертикальный список карточек уровней. Состояния: закрыт (замок и подпись «Пройдите уровень N»), открыт, пройден (звёзды 0–3, лучший HP). Клик по открытому уровню — предбоевой экран: название, брифинг, список башен уровня, «В бой»/«Назад». Заглушка (`implemented: false`) показывается как «Скоро» без входа.
- **Окно результата:** «Повторить», «Следующий уровень» (если открыт и реализован), «В меню/к уровням».
- **Вход в бой по id:** маршрут боя `#/battle/:levelId`; неизвестный или закрытый id — возврат на экран кампании с сообщением. Карта грузится по `LevelConfig.tmj` (не зашитый `desert-base`).
- **Заглушка 2-го уровня** (`id: 'stub-2'`, `implemented: false`, `requires: { levelId: 'desert-base', stars: 1 }`) нужна только для проверки каркаса (замок, разблокировка, список) и не играбельна; реальный уровень 2 — M14.
- **Сохранение v2** — см. §3.3. Первая загрузка v1 мигрирует в v2 без потери `levels`, `settings`, `tutorialDone`, `helpHintSeen`.

## 6. Тестирование и критерии качества

### 6.1 Definition of Done для любой задачи

Все команды должны проходить без ошибок:

```
npm run typecheck   # vue-tsc --noEmit
npm run lint        # eslint
npm run lint:fsd    # steiger ./src — информативно, не блокирует
npm run test        # vitest run
npm run e2e         # playwright, обязательно если менялись UI, ввод или сцены
```

Новая логика в `model/` сдаётся вместе с тестами. Исправленный баг — вместе с регресс-тестом, который до фикса падал.

### 6.2 Unit-тесты (Vitest, без браузера)

- Матрица урона и брони, бонусы рангов, пороги опыта, расчёт возврата при продаже.
- Движение врага по пути с учётом скорости и тиков; утечка в штаб.
- Выбор цели для каждого приоритета.
- Экономика: награда за убийство, бонус досрочной волны, нельзя уйти в минус.
- Спавнер волн: состав и тайминги совпадают с конфигом.
- `progress`: миграция и восстановление после битого JSON.
- Траектории (§4.7): при `t = 0` снаряд в дуле, при `t = 1` в точке цели; вершина дуги `rocket` на высоте `arc` над прямой; за полёт `z` не уходит ниже 0; урон приходит ровно в тик прилёта, а не при выстреле; правила при гибели цели в полёте.
- Пересчёт «клетка ↔ мир» и пикинг «экран → клетка» в `shared/lib/three` — тесты без WebGL (только математика камеры).
- Покрытие `entities/**/model` и `shared/lib/**` — не ниже 80% строк.

### 6.3 Детерминизм и реплеи

- **Тест детерминизма:** один и тот же seed и список команд, два прогона → одинаковый хэш состояния на каждом сотом тике.
- **Golden-реплеи:** в `tests/replays/*.json` лежат записанные партии (`{ seed, levelId, commands: [{tick, cmd}] }`). Тест проигрывает реплей headless и сверяет снапшот итогового состояния. Если снапшот изменился из-за баланса — обновляем осознанно, с объяснением в PR.

### 6.4 Балансные тесты

Headless-прогоны всей карты на x∞, тест занимает меньше 5 с. С M12 тесты параметризованы по `levelId` (`describe.each` по реализованным уровням из `LEVELS`; пороги — поля данных теста на уровень, для `desert-base` — как ниже):

- **Без башен** — поражение не позже волны 3.
- **Эталонная стратегия** (скриптовый бот: фиксированная расстановка и апгрейды) — победа с HP ≥ 10.
- **Только пулемёты** — поражение на волне с дронами и танками, то есть монострой не проходит карту.
- **Нижняя граница:** 50 случайных ботов с разными seed — доля побед в диапазоне 20–80%. Это значит, что карта не тривиальна и не невозможна.

### 6.5 E2E (Playwright)

Проекты: `desktop-chromium`, `mobile` (эмуляция Pixel 7, альбомная ориентация, `hasTouch`) и `mobile-safari` (WebKit, эмуляция iPhone 14, альбомная ориентация).

**Как запускать:**

- `npm run e2e` — headless; так тесты гоняются при обычной проверке.
- `npm run e2e:headed` (`playwright test --headed --workers=1`) — тесты идут в видимом окне браузера по одному, видно каждое действие.
- `npm run e2e:ui` (`playwright test --ui`) — UI-режим Playwright: тайм-лайн, шаги, DOM-снимки, повтор теста.
- При падении сохраняются trace, видео и скриншот (`retain-on-failure`). Посмотреть: `npx playwright show-trace`.
- **Ручная проверка через агента:** Claude открывает игру в видимом окне через Playwright MCP (dev-сервер `npm run dev`), проходит сценарий, делает скриншоты и читает консоль. Так `qa-debugger` воспроизводит баги, которые описаны словами, ещё до того, как написан тест.

1. **Смоук:** главное меню → «Играть» → канвас отрисован, в консоли нет ошибок.
2. **Постройка:** выбрать башню → поставить на buildable-клетку → деньги уменьшились, башня есть в `__game.state`. На небилдабельной клетке постройка запрещена.
3. **Апгрейд и продажа** через панель.
4. **Полный бой:** через `__game` выдать деньги и ускорить до x8 → победа → экран результата → звёзды сохранились после перезагрузки.
5. **Мобильный:** тап → превью → «Построить», pinch-зум не ломает выбор клетки, подсказка про портретную ориентацию.
6. **Пауза на blur:** после `page.evaluate(() => dispatchEvent(new Event('blur')))` тик симуляции не растёт.

E2E кликают по клеткам через `__game.cellToScreen(x, y)`: функция проецирует центр клетки через текущую камеру, поэтому тесты не зависят от угла и зума. Headless Chromium рисует WebGL программно (SwiftShader); если WebGL в CI недоступен, e2e падает явно, без молчаливого пропуска. Пиксели не сравниваем — проверяем состояние через `__game`.

Тесты управляют игрой и проверяют её через `window.__game`. Этот объект есть только при `import.meta.env.DEV || MODE === 'test'`, в продакшн-сборку не попадает — это проверяется тестом на бандл.

### 6.6 Производительность

| Сценарий | Десктоп | Мобильные (средний Android) |
|---|---|---|
| 150 врагов + 40 башен + снаряды | ≥ 60 FPS | ≥ 30 FPS |
| Время до интерактива (prod build) | < 3 с | < 5 с на 4G |
| Память после 3 рестартов боя | без роста > 10% | то же |
| Draw calls в стресс-сцене | ≤ 150 | ≤ 150 |
| Gzip-бандл JS | не больше, чем до перехода на 3D | то же |

Для проверки есть стресс-сцена `?debug=1&stress=1`: команды `grantMoney`, 40 × `placeTower` и `spawnEnemies` (grunt, 150). Снаряды и эффекты берутся из пулов, однотипные меши — из инстансинга. При выходе со страницы боя освобождаются рендерер, геометрии и материалы (§3.5), число WebGL-ресурсов (`renderer.info.memory`) после рестарта возвращается к исходному.

FPS меряется только на реальной видеокарте: `PERF=1 npx playwright test e2e/perf.spec.ts --headed --workers=1`. В headless Chromium WebGL рисует CPU (SwiftShader) — там стресс-сцена даёт ~30–40 FPS, это годится только для сравнения коммитов между собой. Полноэкранные меши (фон, поля) запрещены: фон за картой — `clearColor`.

## 7. Отладка

- **Debug-оверлей** (`F3` или `?debug=1`): FPS, номер тика, число сущностей, draw calls, сетка клеток, buildable-маска, путь, радиусы всех башен, текущая цель каждой башни, хитбоксы (wireframe) и полная траектория каждого летящего снаряда.
- **Параметры URL:** `?seed=123` (фиксированный ГСЧ), `?wave=8` (начать с волны), `?money=9999`, `?speed=8`.
- **Пошаговый режим:** на паузе клавиша `.` продвигает симуляцию на 1 тик.
- **`window.__game`** (только dev/test): `state`, `dispatch(cmd)`, `step(n)`, `setSpeed(x)`, `exportReplay()`, `loadReplay(json)`, `cellToScreen(x, y)`, `setCamera({ yaw, zoom })`.
- **Медленное время:** `?speed=0.25` — полёт снарядов видно покадрово, удобно смотреть траектории.
- **Логгер** `shared/lib/debug/logger`: уровни и теги (`sim`, `render`, `input`, `save`). В prod остаются только `warn` и `error`.
- **Порядок работы с багом:** воспроизвести → `exportReplay()` → положить реплей в `tests/replays/bugs/` → написать падающий тест → исправить → тест зелёный.
- Инструменты: Vue Devtools (Pinia), Chrome Performance для просадок FPS, Memory snapshots для утечек.

## 8. Субагенты для реализации

Файлы агентов лежат в `.claude/agents/`. Основная сессия Claude Code — оркестратор: разбивает этап на задачи, раздаёт их агентам и принимает результат по Definition of Done (§6.1).

| Агент | Зона ответственности | Пишет код в | Инструменты |
|---|---|---|---|
| `sim-engineer` | Симуляция: тик, команды, бой, экономика, волны, ранги | `entities/*/model`, `entities/*/config`, `shared/lib/sim` | read/write/bash |
| `render-engineer` | Three.js: 3D-сцена, модели-заглушки, траектории и эффекты, ввод, камера, тач | `entities/*/view`, `widgets/battlefield`, `features/camera-controls`, `shared/lib/three`, `shared/lib/audio` | read/write/bash |
| `ui-engineer` | Vue: страницы, HUD, панели, меню, сторы, i18n, сохранения | `pages`, `widgets/*/ui`, `features/*/ui`, `shared/ui`, `entities/progress` | read/write/bash |
| `balance-designer` | Числа: статы, волны, цены; балансные тесты | `entities/*/config`, `tests/balance` | read/write/bash |
| `qa-debugger` | E2E, воспроизведение багов, реплеи, перф-замеры, отчёты | `tests/`, `e2e/` (продуктовый код не меняет) | read/write/bash |

Правила взаимодействия:

- Изменения, которые затрагивают зоны двух агентов (например, новая команда симуляции и кнопка в UI), делаем последовательно: сначала `sim-engineer` фиксирует контракт команды или события и тест, потом `ui-engineer` или `render-engineer`.
- После каждого этапа `qa-debugger` прогоняет весь DoD. Строгость FSD на стадии MVP не приоритет.
- Агенты не добавляют зависимости без согласования с оркестратором.

## 10. Открытые вопросы

- Доступность: нужна ли палитра для дальтоников (различать типы врагов не только цветом) и ремаппинг клавиш.
- Музыка и озвучка юнитов («реплики» в духе Generals) — бесплатные CC0-реплики найти трудно, возможно, понадобится TTS или актёр.

- Решено 2026-10-23 (см. CONCEPT §8): сюжетная обёртка — только короткие брифинги по 2–3 строки; бесконечного режима нет; враги могут атаковать башни (пересмотрено 2026-10-23, CONCEPT §10). Названия карт остаются рабочими.
- Когда переходить на честную баллистику с промахами (§4.7) и нужен ли рельеф в симуляции.
- Какие модели заменять на `.glb` первыми и нужен ли единый стиль (low-poly) для всех паков.
- Нужна ли в будущем вторая фракция игрока — от этого зависит, выносить ли конфиги башен в отдельный слайс `faction`.
