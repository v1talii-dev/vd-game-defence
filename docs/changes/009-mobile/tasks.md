# 009 — Мобильные устройства (M13c)

Требования: SPEC §1 (платформы), §3.5 (камера, производительность, PICK), §4.6 (управление, правила тача), §6.5–6.6 (e2e и перф-цели), §9 (M13c). Решение пользователя 2026-10-23: вернуть поддержку мобильных (были отложены с M7 «пока не учитывать»). Исследование и аудит — ниже.
Почему: большая часть тач-основы уже есть с M5/M8 (pointer events, `pointerType`, расширенный PICK на таче, pinch, подтверждение «Построить», coarse-токены 44px, `RotateHint`, safe-area токены, `webglcontextlost`, пауза на `visibilitychange`), но не хватает жестового слоя (`touch-action`), тач-варианта панели башни (U7), кнопок вместо клавиш, профиля качества и проверок. Без этого игра на телефоне неиграбельна.

Правила: срезы по порядку, `[x]` ставит тот, кто прогнал проверку. e2e: максимум 2 воркера, один прогон за раз, только в T7 и T8 (в остальных — unit и ручной проход Playwright MCP в эмуляции). git worktree не использовать; Python нет. Только альбомная ориентация. Баланс и симуляция не меняются (`balance-designer` не нужен); если появится нужда в команде симуляции — сначала контракт `sim-engineer`. Тексты — русские, в `shared/i18n`; коды клавиш — только в `shared/config/hotkeys.ts`.

## Исследование (кратко)

- Подтверждено поиском (качество источников низкое, сверять с играми): двухшаговая постройка «тап → превью → «Построить»» защищает от случайных тапов; кольцо радиуса при выборе; нижняя панель с целями ≥ 44×44 px; продажа с подтверждением; хаптик при постройке (опционально).
- Из общеизвестных практик (не подтверждено поиском): палец закрывает ~15 мм под касанием — ghost и подтверждения выше/сбоку; зона большого пальца — нижние углы в альбомной ориентации; жесты пан/pinch отличать от тапа порогом сдвига; `touch-action: none` на канвасе, `overscroll-behavior: none` на `body`; `100dvh` вместо `100vh`; `env(safe-area-inset-*)` при `viewport-fit=cover`; DPR ≤ 1.5–2, MSAA выключить на слабых; не рисовать при `document.hidden`; `webglcontextlost` с `preventDefault()` и восстановлением; на iOS 17 контекст терялся и у официальных примеров (форум three.js); двойной тап-зум гасит `touch-action` (`manipulation`/`none`).

## Риски

- Эмуляция тача в Playwright не воспроизводит реальные жесты и iOS-особенности (rubber-band, адресная строка, потеря контекста): поэтому ручной чек-лист обязателен.
- Нижняя полоса отнимает высоту у поля в альбомной ориентации (667–844 px × 360–390 px): держать полосу компактной, карта подгоняется по `fitZoom` под оставшуюся высоту.
- Профиль `low` должен оставаться читаемым: стрелки пути, кольца и полоски HP не урезаются, урезаются частицы и следы.
- WebKit в Playwright может быть не установлен локально (Windows): тогда `mobile-safari` проверяется вручную на iPhone.

## Ручной чек-лист для пользователя (реальный телефон)

Как открыть: (а) GitHub Pages `https://v1talii-dev.github.io/vd-game-defence/` после деплоя из `main`; (б) dev-сервер по сети: `npm run dev -- --host`, открыть `http://<IP-компьютера>:5173/vd-game-defence/` в Wi-Fi той же сети (разрешить порт в брандмауэре Windows); (в) Chrome DevTools -> `chrome://inspect` для Android по USB (смотреть консоль и FPS), Safari Web Inspector для iPhone. Для замера FPS добавить `?debug=1`.

1. Альбомная: бой открывается на весь экран, страница не скроллится, нет pull-to-refresh и двойного тап-зума; в портретной — подсказка повернуть.
2. Вырез и жесты: HUD и нижние панели не под вырезом и не под системной полосой жестов.
3. Камера: пан одним пальцем, pinch двумя; жест не ставит и не выбирает башню; после жеста тап работает.
4. Постройка: слот -> видно радиус -> тап по клетке -> ghost виден не под пальцем -> «Построить»; тап по другой клетке переносит; тап мимо отменяет.
5. Башня: тап выбирает, нижняя полоса не закрывает башню; улучшение, отмена, продажа (с подтверждением), ремонт, руины -> «Восстановить»/«Убрать» — всё пальцем.
6. HUD: следующая волна, пауза, скорость; все кнопки удобно нажимать большим пальцем двумя руками.
7. Производительность: стресс-сцена `?debug=1&stress=1` держит ≥ 30 FPS, телефон не греется за 5 минут боя; запись FPS и модель телефона — в отчёт.
8. Системное: свернуть браузер и вернуться — бой на паузе, картинка не пропала; заблокировать и разблокировать экран; повернуть экран во время боя; входящий звонок/уведомление.
9. Окна: кампания, настройки, результат — прокручиваются пальцем, кнопки крупные.
10. Сообщить: модель, ОС, браузер, что неудобно (размер кнопок, перекрытие пальцем, лаги).

PWA/установка на главный экран, принудительный полноэкранный режим, портретный режим, жесты поворота камеры, жест «щипок для выбора диапазона», отдельная раскладка для планшетов, звук, серверный телеметрический сбор FPS.
