# 007 — Удобство боя (M13)

Требования: SPEC §3.5 (кольца, стрелки пути), §4.3 (бесплатная отмена), §4.6 (предпросмотр радиуса, панель башни у башни), §9 (M13); решения пользователя 2026-10-23. Исходное описание U7 — `docs/changes/archive/002-ui-redesign/tasks.md`.
Почему: игроку трудно читать маршрут при нескольких входах, ошибочную постройку жалко продавать за 70%, радиус виден только после постановки, панель башни далеко от самой башни, кольца-индикаторы мелкие.

Правила: срезы по порядку, `[x]` ставит тот, кто прогнал проверку. e2e: максимум 2 воркера, один прогон за раз, только в X3, X4, X5 и X7. git worktree не использовать. Сначала контракт симуляции + тест, потом рендер и UI. Только десктоп (мобильные отложены). Поведение боя, реплеи и балансные тесты не меняются, кроме правила возврата в X1 (там снапшоты правятся осознанно, если какой-то реплей продаёт башни).

## Срезы

- [ ] **X1. Правило бесплатной отмены.** (`sim-engineer`; можно сразу, параллельно с M12 C2–C5: файлы `entities/battle/model/*`, `entities/tower/config`) Константа `FREE_REFUND_SECONDS` (стартово 10) в `entities/tower/config`; башня хранит `paidTick`; при продаже возврат 100% всех вложений, если волна не идёт (фаза подготовки: до первой волны и в паузах) или с `paidTick` прошло не больше N секунд в тиках, иначе 70% (SPEC §4.3). В состоянии/снимке башни — `sellRefund` (сколько вернётся сейчас), чтобы UI не считал сам. Событие `towerSold` несёт реальный `refund`.
  Проверка: unit: продажа в паузе = 100%; в бою через N с после оплаты = 70%; в бою внутри окна = 100%; граница ровно N с; башня с улучшениями; продажа строящейся (как раньше 100%); тест детерминизма и golden-реплеи, `npm run typecheck`, `lint`, `test`.
- [ ] **X2. Заметные кольца-индикаторы.** (`render-engineer`; сразу, параллельно с X1; файлы `shared/lib/three/hud.ts` и вызовы в `three3d.ts`) Кольца стройки, улучшения и ожидания: диаметр 0.45–0.5 клетки (было 0.36), толще линия, тёмная подложка или контур для контраста на песке, ярче цвета; по-прежнему над моделью и не закрывает её; шевроны ранга по тем же размерам. Константы размеров — в одном месте.
  Проверка: скриншот (Playwright MCP, одно окно) на песке и на дороге: кольца заметны, модель башни полностью видна, ничего не перекрыто; typecheck, lint, test. e2e не нужен.
- [ ] **X3. Стрелки пути.** (`render-engineer`; после X2, тот же `three3d.ts`) Новый модуль в `shared/lib/three` (бегущие шевроны по `roadSegments`, общий InstancedMesh, без аллокаций в кадре); запуск в начале боя и по событию старта волны, 2–3 с, затем гаснут; несколько входов — несколько маршрутов (проверяется юнит-тестом на данных с двумя путями); `prefers-reduced-motion` — статика.
  Проверка: unit: генерация позиций стрелок по сегментам, в т.ч. два пути; e2e/скриншот: стрелки видны сразу после «В бой» и после старта волны, потом исчезают; перф `PERF=1 --headed` не хуже прежнего; typecheck, lint, test.
- [ ] **X4. Предпросмотр радиуса при наведении на слот.** (`ui-engineer` затем `render-engineer`; после X2) а) `ui-engineer`: в сторе боя `hoveredBuildType` (mouseenter/leave и фокус слота в меню построек, без опроса каждый кадр). б) `render-engineer`: кольцо радиуса на земле у курсора (или над клеткой под курсором), радиус из конфига башни, без аллокаций; уходит при потере наведения. Файлы: `features/build-menu` (или аналог) и стор; `three3d.ts` после X3.
  Проверка: e2e: наведение на слот показывает кольцо (через debug-API/DOM-признак), уход скрывает; скриншот; typecheck, lint, test.
- [ ] **X5. U7 Панель башни у башни.** (`ui-engineer`; после X1 для `sellRefund` и после M12 C4, потому что правит `pages/battle`/`BattleHud`, как и C3/C4) Панель выбранной башни рядом с ней по экранной проекции (`cellToScreen`), следует за камерой при пане и зуме, флип стороны и кламп у краёв экрана, не перекрывает модель; кнопка «Продать» показывает фактический возврат из `sellRefund` (100% или 70%); прежнее место справа убирается; `data-testid` и горячие клавиши не меняются.
  Проверка: e2e при разных положениях камеры и башнях у всех краёв карты: панель в пределах окна, следует за башней при пане, улучшение/продажа/приоритет работают; скриншоты 1280×720 и 1920×1080; typecheck, lint, test.
- [ ] **X6. Окно N и баланс.** (`balance-designer`; после X1, параллельно с X2–X5, файлы `entities/tower/config`, `tests/balance`) Подобрать `FREE_REFUND_SECONDS` (10 с — старт), убедиться, что боты и эталон не используют продажу как эксплойт; числа прежних балансных порогов не меняются.
  Проверка: `npm run test`, пороги §6.4 прежние.
- [ ] **X7. Приёмка M13.** (`qa-debugger`; последним) Полный DoD, один прогон e2e (≤ 2 воркера), ручной проход через Playwright MCP: стрелки, отмена за 100%, превью радиуса, панель у башни, кольца; обновить `PROGRESS.md` и SPEC §9, пакет перенести в `docs/changes/archive/`.

Мобильные и тач-полоса (только описано в SPEC), звук, честная баллистика, рельеф, бесконечный режим, влияние врагов на башни; новые башни и уровни — M14+ (CONCEPT §7).
