# 005 — Очередь улучшений, единая раскладка клавиш, кадр карты, единый индикатор

Требования: SPEC §3.5, §4.3, §4.6, §9 (M11).
Почему: нельзя запланировать улучшение при нехватке денег; горячие клавиши разбросаны (`input3d.ts:152-175`, `attachCameraControls3d.ts:116-121`, подписи в `ru.ts:62,80`), `S` одновременно продаёт башню и двигает камеру (поэтому пан отключается при выбранной башне, `input3d.ts:41`); карта на старте маленькая в центре на чёрном фоне (`three3d.ts:81`, `rig.ts:42`); индикаторы разных стилей.

Правила: срезы по порядку, `[x]` ставит тот, кто прогнал проверку. e2e: максимум 2 воркера, один прогон за раз, один прогон на срез. Сначала контракт симуляции + тест, потом рендер/UI. Спиннер «ожидание» и голограмма уже сделаны в P3 (004): K4 только добавляет «ожидание» для запланированного улучшения.

## Развилки (решены пользователем 2026-10-23)

- R1. Модель запланированного улучшения: башня остаётся `active` + поле `upgradeOrder: number | null`; альтернатива — новая фаза `upgradeQueued` (ломает проверки `phase !== 'active'` по всему коду).
- R2. Раскладка: `WASD`/стрелки пан, `Q`/`E` предыдущая/следующая башня, `R` (и `U` как дубль) улучшить, `X`/`Delete` продать, `Space` волна, `P` пауза, `F` скорость, `Esc` отмена. Альтернативы: `Space` = пауза, волна = `Enter`; продажа `Shift+S`.
- R3. Кадр: стартовый zoom «карта заполняет экран» + внешнее поле земли с туманом + мин. zoom по вьюпорту; альтернатива — только обои/градиент неба.
- R4. FIFO общая очередь: заказ улучшения блокирует следующие заказы построек; альтернатива — отдельные очереди.
